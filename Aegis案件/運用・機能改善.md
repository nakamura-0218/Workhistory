# A1システム 非機能要件改善 アウトプット
システム構成、運用、コスト削減等の観点で改善した実績は主に以下
- システムの全体コストを45%削減（毎月約60万）
- セキュリティ強化
- アプリチームの開発環境の向上
- 運用・監視基盤の構築  

以下は、Terraformによりコード管理

## IAM
- 各IAM User（IAM Group）の権限改善
- EC2、ECS、のIAM Role作成

## VPC
- NAT Gatewayを1つから3つに変更し、各AZのprivate subnet用のroute tableを作成。デフォルトルートに各AZのNAT Gatewayを経由するルートを追加
- subnet / NAT Gateway / EIP / route table の命名規則を統一
- S3 Gateway型VPCエンドポイントを追加し、private subnetのroute tableにルートを追加⇒ECSイメージpullなどのS3との通信量を無料に

## EC2
- Webポータルプロジェクトのセキュリティグループを作成
- ローカル環境から、DB接続するためのSSMポートフォワーディング + バッチ処理用EC2インスタンス構築
- AMI取得、復元

## ECS
- Container Insightsの有効化
- ECS単一タスクによるバッチ処理

## ALB
- セキュリティポリシー（TLSバージョン・暗号スイート）をAWSが推奨している値に変更
- アクセスログ / コネクションログを有効化
- 削除保護を有効化

## S3
- バケットの命名規則を制定
- ALBログ格納用バケット作成、バケットポリシーの設定
- バケット内の不要なオブジェクトを削除する、ライフサイクルルール設定

## Aurora
- AuroraのACU調整（コスト削減）
- 社内のローカル環境(DB developerツールpgadmin等)から、SSMポートフォワーディング経由でAuroraへセキュアに接続できる環境を構築
- 毎晩、Eventbridgeスケジューラーを使用した、ECS単一タスクによるバッチ処理（prd auroraのスナップショットをdev環境に復元し、dev auroraのデータベースに同期するバッチ処理）

## Event bridge
- スケジューラー機能を使用したバッチ処理の自動化

## Secrets Manager
- シークレットの追加
- 自動ローテーション設定

## Amazon Q Developer in chat applications + SNSトピック
- リソース使用量の増加、障害、エラー等のステータスを検知して、slackに通知する監視基盤の構築

## 設計・ドキュメント
- SSHポートフォワーディングによる test DB 接続手順書を作成
- Webポータルプロジェクトの工数見積もり、簡単なドキュメント作成
