
# A1システム 閉域化対応 アウトプット

イージス・ワークス株式会社 A1システムにおける、AWS環境の閉域化（インターネット経路の排除・通信経路の最小化）対応の実績。

- 期間：2026年6月〜2026年7月（継続中）
- 稼働：6月 11日 / 39:10h、7月 19日 / 149:53h（合計 30日 / 189:03h）
- 役割：AWSインフラ設計・構築（Terraform / IaC）、調査・設計・実装・レビュー・ドキュメント作成

---

## 1. 実績サマリ（テーマ別）

### 1.1 現行環境の調査・方式設計
- 現行システム構成およびネットワーク経路の調査
- CloudFront / ALB を中心としたセキュリティ面の調査
- 既存ドキュメント・先行検討資料の読み込みとキャッチアップ
- 閉域構成化に向けた全体手順（移行ステップ）の策定
- 閉域化構成におけるドメイン設計
- AWS構成図の作成（閉域化前 / 閉域化後）
- Backlogチケットの起票によるタスク管理

### 1.2 ALB のセキュリティ強化
- dev環境 ALB セキュリティグループの設定（プルリク作成まで）
- セキュリティグループの更新・prd環境用設定の作成および apply 依頼
- ALB セキュリティポリシーの調査・暗号スイートの確認
- セキュリティポリシー変更に伴う影響調査
- dev環境への ALB セキュリティポリシー適用および接続確認
- 本番環境（prd）への ALB セキュリティポリシー apply
- ALB 削除保護の設定追加

### 1.3 ALB ログ基盤（S3）の設計・構築
- ALB アクセスログ / コネクションログの設計（S3バケット命名規則の制定を含む）
- S3バケットの作成およびバケットポリシー設定（dev → prd）
- ALB アクセスログ / コネクションログの有効化
- S3 レプリケーション設定のレビュー
- S3バケットのライフサイクル設定変更
- S3 サーバーバージョニング削除PRのレビュー

### 1.4 VPCエンドポイントによる閉域経路化
- VPCエンドポイントの設計調査
- Terraform による VPCエンドポイント定義の実装
- dev環境への apply および動作確認
- prd環境への適用および動作確認
- apply 失敗時の原因調査・解消
- 不要なインターフェース型VPCエンドポイントの削除設定（PR作成）
- VPCエンドポイント導入に伴うコスト削減対応

### 1.5 ネットワーク構成の再設計（VPC / Subnet / ルーティング）
- NAT Gateway とアタッチ先 route table のルート追加・設定修正
- NAT Gateway（prd）の復旧対応、route table 変更
- NAT Gateway prd への apply と動作確認
- dev環境 VPC の再作成検討および実施・動作確認
- subnet構成の変更（isolated subnet の追加）：dev → prd
- subnet / NAT Gateway / EIP / route table の命名規則統一
- VPN 接続方式の調査

### 1.6 DNS・証明書
- Route53 レコードの追加
- ACM 証明書の発行
- セキュリティグループの新規作成（閉域化構成向け）

### 1.7 IaC（Terraform）品質・運用改善
- Terraform 実行環境および Git 環境のセットアップ
- Terraform 定義形式の修正・コードリファクタリング
- `terraform plan` のドリフト修正
- レビュー指摘事項の取り込み（ALBセキュリティポリシー・S3バケット）
- プルリクエストのレビュー対応（#103 ほか複数）

### 1.8 データベース・検証環境
- DB モニタリング設定の修正および prd 適用
- RDS Performance Insights の動作確認
- prd DB のデータを dev / test DB へコピーする方式の検討
- 社用PCから SSH ポートフォワーディング経由で test DB へ接続する対応
- 上記接続手順のドキュメント作成
- test環境 Web ポータルサイト構成の構築
- ECS フロントエンドの検証
