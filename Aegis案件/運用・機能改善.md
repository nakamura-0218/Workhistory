# A1システム 閉域化対応 アウトプット

AWSのサービス／リソース単位で実績を記載する。
追記する際は該当する見出しの配下に箇条書きを足し、扱うサービスが増えた場合は新しい見出しを追加する。

---

## VPC（Subnet / Route Table / NAT Gateway / EIP）

- isolated subnet を追加した subnet 構成へ変更し、dev / prd 両環境へ適用
- NAT Gateway と route table のルート設定を修正し、prd 環境の疎通を復旧
- dev環境の VPC を新構成で再作成
- subnet / NAT Gateway / EIP / route table の命名規則を統一

## VPCエンドポイント

- Terraform で VPCエンドポイントを定義し、dev / prd 両環境へ適用
- AWSサービス向け通信をインターネット経由から VPCエンドポイント経由へ切り替え
- 不要なインターフェース型VPCエンドポイントを削除し、コストを削減

## セキュリティグループ

- 閉域化構成向けのセキュリティグループを新規作成

## ALB

- セキュリティポリシー（TLSバージョン・暗号スイート）を強化
- アクセスログ / コネクションログを有効化
- 削除保護を有効化

## Route 53

- 閉域化構成向けのレコードを追加

## ACM

- 閉域化構成向けの証明書を発行

## S3

- ALBログ格納用バケットの命名規則を制定
- ALBログ格納用バケットとバケットポリシーを Terraform で構築（dev / prd）
- バケットのライフサイクル設定を変更

## RDS

- DBモニタリング設定を修正し、prd 環境へ適用
- 社用PCから SSHポートフォワーディング経由で test DB へ接続できる環境を整備

## ECS

- test環境の Webポータルサイト構成を構築

## Terraform / IaC

- Terraform 実行環境および Git 環境を構築
- Terraform コードのリファクタリング・定義形式の統一
- `terraform plan` のドリフトを解消
- プルリクエストのレビュー（#103 ほか複数）

## 設計・ドキュメント

- 閉域構成化の移行手順書を作成
- 閉域化構成のドメイン設計を策定
- AWS構成図を作成（閉域化前 / 閉域化後）
- SSHポートフォワーディングによる test DB 接続手順書を作成
