# A1システム 閉域化対応 アウトプット
CloudFront + S3 + Internet-facing ALB + Backend ECS + Auroraのインターネット公開構成から、オンプレ(社内環境) ⇒ Site to Site VPN ⇒ Internal ALB + Frontend ECS + Backend ECS + Auroraという閉域化構成に変更に伴う作業の実績を以下に列挙。
以下変更内容は、全てterraformにてコード管理

## VPC
- Public Subnet + Private Subnetの2層構成から、Public Subnet + Private Subnet + Isolated Subnetの3層構成へ変更

## EC2
- 閉域化構成向けのセキュリティグループを新規作成
- ターゲットグループ作成

## ALB
- Internal ALB構築
  - フロントエンドECS+バックエンドECSへパスベースルーティングで振り分けるリスナールール設定
  - ヘルスチェック設定
  - セキュリティ(セキュリティポリシー、HSTS、CSP、SSL/TLS証明書等)、ログ(アクセスログ、コネクションログ)
 
## Route 53
- Private Hosted Zoneに閉域化構成向けのレコードを追加
- Public Hosted ZoneからPrivate Hosted Zoneへの切り替え作業

## ACM
- 閉域化ドメイン用の証明書発行

## ECS
- CloudFront + S3 + Internet-facing ALB + Backend ECS 構成から Internal ALB + ECS Frontend(Nginx) + ECS Backend 構成に変更

## Secrets Manager
- シークレット追加

## Aurora
- private subnetからisolated subnetへの移行

## 設計・ドキュメント
- 閉域構成化の移行手順書を作成
- 閉域化構成のドメイン設計を策定
- AWS構成図を作成（閉域化前 / 閉域化後）
